## Done tickets

### KIT-001 — spike runbook

`docs/spike-runbook.md`: the seven acceptance tests in `docs/spike.md` as an executable checklist for the Vega
Virtual Device and a Fire OS stick, mapped 1:1 onto `docs/device-matrix.md`. Cold-reviewed; 17 findings
applied, 7 of them day-burners in the harness code. Two headline findings confirmed against primary sources
and recorded in **decision 0002**: `VideoPlayer` is a TypeScript class, not a React component (so
`vega.tsx:88` cannot work — the adapter is a rewrite, KIT-010, not the rename its header claims); Shaka is
vendored from v4.8.5 with Amazon's 44-patch series and attached via the constructor, never `.attach()`. A
custom `textDisplayFactory` is still honoured, so both halves of the `vega.tsx:77` decision stay open.
`Platform.OS` on Vega is `'kepler'` (Amazon's doc types it `enum('kelper')`, a typo).

### KIT-009 — `preferredText` never delivered cues

`selectedText` gated cue delivery but was populated only by `api.selectText`; the `preferredText` path
called the adapter directly and bypassed it, so every fetched VTT was dropped and `onCue` never fired — the
README's own example path. Fixed by one shared `selectText` transition; logic extracted to a pure
`src/player/selection.ts` (not `core`, to keep the public surface flat). Fixing the gate **unmasked** a
latent bug: `pickText` treated `kinds: []` as "all" (empty array is falsy), and `described` passes `kinds: []`
for captions-off. **Decision 0003:** explicit `[]` means none; omitted `preferredText` means none; fixed in
both `pickText` and KitPlayer. `described` needed no change. Also: deselecting while paused now clears the
overlay (`removeTrack` never notified). Reviewer found KIT-011/012/013/014 as pre-existing and they were
ticketed rather than folded in. Every new test verified red against pre-fix code, including one gap the
orchestrator found where a harness test guarded a copy of the logic rather than the real guard.

### KIT-002/003/004 — HLS master-playlist parsing

`src/core/hls.ts` (pure parser, public via `./core` — `described/packages/pipeline` imports core in four
files, and `./player` cannot load in Node) + `src/player/hls.ts` (fetch layer, injectable `fetch`).
`resolveUrl` is hand-written per RFC 3986 because React Native's `URL` concatenates. `fetchHlsVtt` moved
**byte-identical** (diffed against HEAD). **Decision 0004:** `x-kit-text-urls` deprecated for one release
with a one-time warning, override-by-id merged after manifest tracks, removed next minor — `described`'s
TrackSheet ids only resolve through the header map today. Planning surfaced that `described`'s text ids
**never matched the kit's** (app composes `captions-en`; `fromRnvText` uses the ExoPlayer index). Both
adapters emit `onTracks` exactly once after the manifest resolves, because `appliedPrefs` latches on the
first call — the KIT-009 bug by another route. 15 mutations run; 3 survived and produced extra guards (header
merge order, header-only ids, and the web ordering guard the orchestrator's own mutation exposed).

The five `adapter wiring` tests are **structural guards**: no DOM or RN test environment, so they pin the
shape of correct code. A behaviour-preserving refactor that changes the shape will fail them — read the
comments and update the guard deliberately, do not delete it. If KIT-005 can assert `onTracks` ordering
against a real `<video>`, the web guard can retire.

## Open tickets — detail

### KIT-014
A *present but empty* preference selects **every** text track, descriptions included, because "omitted key
means any" (decision 0003). `preferredText={{ languages: userLangs }}` with `userLangs === undefined` therefore
turns on every language at once — the KIT-009 footgun one level up. Behaviour is pinned by
`test/selection.test.ts › pins that a present-but-empty preference selects every track`. Semantic change;
the human decides.

### KIT-011
`KitPlayer.tsx`: `appliedPrefs`, `selectedText` and the scheduler's tracks are never reset when `props.source`
changes. A second source inherits the previous ids and stale cues (fireos/Shaka ids are small integers and
collide), and `preferredText` is never re-applied.

### KIT-012
An inline `onCue` rebuilds the `CueScheduler` every render, dropping every loaded track — latent, because the
README and both apps pass a stable `setCues`. Separately `api` is rebuilt on every position tick
(`getPosition` closes over `position` state), churning `useImperativeHandle` and `renderControls` at ≤ 4 Hz.

through a Metro alias, not a kit dependency. The `vega.tsx:12` header comment is false and goes with the
rewrite. Public interfaces unaffected. Should build `Tracks.text` from `loadHlsTextTracks` for identical ids
